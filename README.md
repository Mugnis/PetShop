# 🐾 Go Pet Shop

**Go Pet Shop** — это учебный проект интернет-магазина товаров для питомцев, написанный на Go с использованием PostgreSQL.  
Он создан для отработки навыков работы с SQL-запросами, транзакциями и построения REST API.

---

## 🚀 Основная идея

Проект моделирует классический онлайн-магазин с товарами, пользователями, заказами и оплатами.  
Цель — показать полный цикл разработки от работы с базой данных и CRUD-операций до реализации транзакций и аналитики.

---

## 🔑 Возможности проекта

- 📦 Управление товарами (добавление, обновление, удаление, просмотр списка и конкретного товара).  
- 👤 Работа с пользователями (регистрация, получение списка и конкретного пользователя).  
- 🛒 Создание заказов и добавление позиций.  
- 💳 Оформление заказов в транзакции (уменьшение остатков, создание заказа, позиций и транзакции оплаты).  
- 📊 Просмотр истории заказов и аналитики (популярные товары, детали заказов и транзакций).  
- ✅ Health-check для проверки состояния сервера.

---

## ⚙️ Технологии

- **Go** — основной язык разработки.

## 🛠 Как запустить

1. Клонировать репозиторий:
   `git clone https://github.com/Mugnis/PetShopTests.git`
   `cd go-pet-shop`

2. Настроить окружение: скопировать `.env.example` в `.env` и поправить логин, пароль и имя базы.
`cp .env.example .env`

3. Поднять PostgreSQL и применить миграции:
`docker compose up -d postgres`
`task migrate`

4. Запустить сервер (конфиг `config/local.yaml`, другой выбирается через `APP_ENV`):
`go run ./cmd/app`

5. После этого API будет доступно по адресу:
`http://localhost:8080`, проверка — `GET /health`.

Всё сразу в контейнерах: `docker compose up -d --build` (приложение берёт `config/dev.yaml`).

## 🧩 Версии приложения

### Версия 1: Базовый CRUD

- Что нового: Появляются базовые таблицы users и products.
- Суть изменений: Реализуется самый простой слой работы с базой — одиночные запросы SELECT, INSERT, UPDATE, DELETE без связей между таблицами.
- Что умеет сервис: Регистрировать пользователей, управлять каталогом товаров и отдавать данные по простым запросам.

### Версия 2: Связи между таблицами

- Что нового: Добавляются таблицы orders (шапка заказа: кто заказал и когда) и order_items (состав заказа: какие именно товары и в каком количестве лежат внутри).
- Суть изменений: Появляются внешние ключи (FOREIGN KEY) и связь «один ко многим» (у одного пользователя много заказов, в одном заказе много позиций). В SQL-запросах впервые используются JOIN, чтобы склеивать данные из разных таблиц в один ответ.
- Что умеет сервис: Создавать пустой заказ, наполнять его товарами по одной позиции за запрос и смотреть список заказов конкретного пользователя.

### Версия 3: Атомарность и защита от гонок

- Что нового: Появляется таблица transactions (записи об оплате) и единая ручка POST /checkout.
- Суть изменений: Вместо разрозненных запросов из Версии 2 оформление покупки объединяется в одну ACID-транзакцию (BEGIN ... COMMIT / ROLLBACK). Вводится защита от отрицательных остатков на складе (WHERE stock >= $1) — если два человека одновременно купят последний товар, второй получит отказ, а его заказ не создастся.
- Что умеет сервис: Оформлять покупку целиком за один шаг — списывать остатки со склада, создавать заказ, записывать товары и фиксировать оплату так, чтобы при любом сбое база откатывалась в исходное состояние.

### Версия 4: Аналитика и сложные выборки

- Что нового: Новых таблиц нет — добавляются только аналитические методы и DTO-модели (OrderDetail, PopularProduct).
- Суть изменений: Усложняются SQL-запросы на чтение. Используются множественные JOIN (сборка данных сразу из 4 таблиц: users + orders + order_items + transactions) и агрегация с группировкой (GROUP BY, SUM, ORDER BY).
- Что умеет сервис: Выводить полную детализированную историю покупок пользователя со статусами оплаты и считать топ самых продаваемых товаров магазина.
